# Product-writing checklist

## Selected source guidance

- Start with the reader's main need and make the next decision visible.
- Remove excess words while retaining necessary information.
- Prefer familiar, conversational wording over jargon.
- Use contractions where they suit the context.
- Use sentence case for headings and labels while preserving names.
- Usually omit a final period or colon from titles and UI headings.

Source: Microsoft's
[top tips for style and voice](https://learn.microsoft.com/en-us/style-guide/top-10-tips-style-voice).
This is a selected paraphrase, not the entire guide.

## Project error-copy review

Use only the facts available:

1. State the failed task in terms the reader recognizes.
2. Supply an available recovery step.
3. Keep diagnostic detail available when the audience needs it.
4. Check that a reassurance about saved work, privacy, timing, or retry safety
   has evidence.

When the cause is unknown, describe the observed problem without guessing.
When a button exists, reuse its actual label.

These error-copy steps are the project's editorial workflow.
